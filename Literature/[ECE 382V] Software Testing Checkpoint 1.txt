Progress
We’ve looked through supporting papers, primarily focusing on “NonDex: a tool for detecting
and debugging wrong assumptions on Java API specifications”. We decided to use the same
client projects that were used in NonDex: Checkstyle, Apache Jackrabbit Oak, JGraphT, and
others. We have decided to use an open-source LLM (GLM-5.3, Deepseek V4, Kimi K3) on the
TACC machines as a way to read specifications for APIs the client projects use and generate
modified versions of the functions/output. Based on the API calls used in the client projects, we
could investigate the specifications for that particular method within those APIs. However, we
can start with APIs that NonDex currently covers such as Object hashCode(), HashMap keySet(),
values(), entrySet(), ConcurrentHashMap elements(), values(), etc.


The evaluation guidelines for our project would revolve around how much more progress we
made relative to the results in NonDex. The original methodology required manually creating a
modified version of the API call and using NonDex to replace these calls at runtime. This would
take a long time and possibly could hinder progress. Our metrics for success are driven by how
many more non-deterministic caused bugs we can find using our LLM-based methodology
relative to the paper’s manual implementation of NonDex. Additionally, we could report how
long it took to run our agentic workflow from start to finish and make these changes.


The agentic workflow we’ve generally come up with:
   1.​ A script identifies all the API calls executed for a specific test.
   2.​ For each API, an agent searches for and reads the associated documentation and
       determines if it is nondeterministically specified. If so, continue to step 3. Otherwise,
       move to the next API call.
   3.​ An agent uses the current implementation of the API as a starting point, but legally alters
       its functionality with a different implementation directly addressing the nondeterministic
       specification. Trigger NonDex on the test with modified function behavior.
